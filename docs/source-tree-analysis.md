## Critical paths

| Path | Why it matters |
|---|---|
| `src/app/api/` | The full HTTP contract a mobile client would consume. Every business rule lives here. |
| `prisma/schema.prisma` + `prisma/migrations/` | Source of truth for the data model. |
| `src/lib/auth.ts` + `middleware.ts` | Session and route-protection logic. The biggest gap for native mobile (cookie-based). |
| `src/lib/ai.ts` + `src/lib/extract.ts` | Recipe ingestion pipeline. Server-only (Gemini key + page fetch). Mobile cannot replicate locally. |
| `src/lib/recipe-images.ts` | Image fallback chain — explicit URL → cuisine → dish → protein → gradient. Worth re-implementing identically on mobile so cards render the same. |
| `src/lib/constants.ts` | Tag vocabularies. The lists are the contract — clients must use exactly these strings. |
| `src/hooks/use-feed-polling.ts` | The current "real-time" mechanism. Mobile would replace with push or sockets. |

## Entry points

- **HTTP**: every `src/app/**/route.ts` and `src/app/**/page.tsx`. The Next.js dev server serves both.
- **CLI**: `npm run dev`, `npm run build`, `npm run start`, `npm run db:migrate`, `npm run db:seed`.
- **Build-time**: `postinstall` runs `prisma generate` to produce `src/generated/prisma/`.
